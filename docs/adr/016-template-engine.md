# ADR-016 — Template engine

- **Status:** **Accepted** (25 Nov 2026). Design checkpoint approved (Q8).
- **Context:** MP §3.3–3.4, §10 and §12; spec §5.1 and §6.1–6.5; plan `docs/plan/phase-03.md` (decisions P3-A … P3-G); ADR-000 (CSP with prerendered shells, `/theme.css`).

## Context

Each school picks one of four website templates: Institutional Classic, Modern Academic, Heritage & Prestige and Contemporary Community. A school must be able to switch at any time **without touching its content**, and preview a template before choosing it.

Two further constraints:

- The public site must stay fast on mid-range Android phones (MP §1, §10).
- It must pass the nonce-based CSP with prerendered shells (ADR-000).

## Decision

### 1. Templates are presentation only

- A template is a `TemplateDefinition` (`src/features/templates/types.ts`): `Header`, `Footer`, `PageFrame`, the section components it designs itself, where the homepage `h1` goes, and provisioning defaults.
- The registry is a static map from template key to definition.
- Templates receive typed props and **never query the database**:
  - Data comes from cached loaders in `shared/loaders` through the server-side section registry (`shared/sections.ts`).
  - An ESLint rule forbids Supabase clients and `*/queries` imports anywhere else under `src/features/templates`.
- Any section type a template doesn't design is drawn by a shared fallback, styled by that template's tokens. So **switching never drops a section** (spec §6.3).

### 2. CSS scoping

- The template wrapper carries `data-template="…"`. Each template's `tokens.css` sets `--tpl-*` variables under that selector.
- One global `@theme inline` block in `globals.css` maps Tailwind's `tpl-*` colours, fonts and radii onto those variables.
  - Tailwind v4's `@theme` is global, so four per-template blocks would collide.
  - **Every token used as a utility must be mapped there.** An unmapped class compiles to nothing: Phase 3 found the strong rule colour missing, which hid slideshow dots, frames and the timeline line.
- Shared template classes live in `@layer components`, beneath utilities, so a template can adjust a shared class with a utility.
- Brand colours and fonts still come from `/theme.css` (ADR-000). Templates hard-code only neutral tones such as paper and ink.

### 3. Fonts

- Fonts stay on `next/font` with `display: swap` (MP §10).
- next/font's metric-matched fallback faces use `local(Arial)` and `local(Times New Roman)`. **Android phones and Linux have neither.** Unadjusted fallbacks there made text jump when the web font arrived (CLS 0.19 at 1280 px).
- `src/lib/fonts/fallbacks.css` adds matched faces for Roboto and Noto Serif (Android) and DejaVu (Linux).
  - It is generated by `scripts/generate-font-fallbacks.mjs`, using Next's capsize metrics and the same formula as next/font.
  - Each family's stack is the web font, next/font's fallback, then ours (`fontStack()`).
- **Residual:** matched widths are approximate, so on a cold first visit a long headline can still rewrap by one line when the font arrives. The E2E suite measures layout stability with fonts held back, and records the swap separately.

### 4. Statistics as a timeline (P3-F)

Heritage & Prestige renders the `statistics` section as a milestone timeline (value = year, label = milestone). It's the same data, presented differently, so no new section type is needed.

### 5. Rich text (P3-E)

- Sections with rich text render it on the server with Tiptap's static renderer and one shared extension list (`src/lib/rich-text`). No client JavaScript is involved.
- Only safe link protocols are allowed, and links stay in the same tab.
- The Phase 4 editor reuses the same extension list.

### 6. Demo gallery (P3-C)

- `/preview/demo/[key]` shows every section type with typed demo fixtures. `/preview/demo/[key]/page/[layout]` shows the page frame in its three layouts.
- The gallery is used for the design checkpoint, `preview.png`, accessibility tests and screenshots.
- It returns 404 when `VERCEL_ENV=production`, and it is `noindex`.
- Modules without tables yet (news, events, gallery, academics, leadership) appear only there. Their homepage loaders return nothing until their phases.

### 7. Preview links (P3-D)

- `createPreviewToken` (`appearance.manage`) returns `/preview/template/[key]?t=…`.
- The token:
  - is HMAC-signed with `PREVIEW_TOKEN_SECRET` and lasts 10 minutes
  - is **bound to the user who asked for it and to the template**
  - carries unsaved theme and homepage overrides, up to 4 KB (larger drafts wait for Phase 5's `content_drafts`)
- The route:
  - requires a session and `appearance.view`
  - merges the overrides into the saved settings in memory, and **never writes**
  - sends `Cache-Control: private, no-store` and `noindex`
  - is the only route that may be framed, and only by this site: CSP `frame-ancestors 'self'` and `X-Frame-Options: SAMEORIGIN`
- Phase 5's appearance screen embeds it.

### 8. Motion and materials

Follows the Apple design guidance and the motion studies from 21st.dev:

- **Motion:**
  - Only `transform` and `opacity` animate.
  - One hero entrance on load, and one scroll-driven moment per page: Modern Academic's photograph settles; Heritage's timeline draws in the school's colour.
  - Scroll-driven motion uses CSS scroll and view timelines, on the compositor, never JavaScript per frame.
  - All motion is off under reduced motion.
- **Slideshow:** the controls are one capsule, and the active dot's fill _is_ the timer. Hover, focus or pause freezes both, so they can't drift apart (WCAG 2.2.2).
- **Liquid glass** appears only on the floating control layer: headers, the slideshow capsule and dropdowns. It is a tint, blur with saturation, a specular rim and a soft shadow.
  - Blur is limited to fine pointers. Touch devices get a firmer tint with no blur, because blur costs GPU time on every scroll frame.
  - SVG refraction (`backdrop-filter: url()`) is not used: Chromium-only, and it costs every frame.
  - Reduced transparency and higher contrast get solid surfaces.

### 9. JavaScript on public pages

- **Islands:**
  - the hero slideshow
  - the menu helper (Escape, outside click and route-change closing for native `<details>` menus, which work before JavaScript)
  - the nav link that marks the current page
- **Island rules:**
  - Islands avoid `tailwind-merge` and icon runtimes.
  - The CSP nonce helper for Radix overlays loads only in the admin layout.

## Consequences

- **Switching templates changes nothing but `theme.template`.** This is proven by `template-switch.int.test.ts`: 36 tables, row counts and checksums; one audited `settings.updated` row per switch. Evidence: `docs/plan/evidence/phase-03/`.
- **The 120 KB first-load JavaScript budget (MP §10) can't be met as written.** Next.js 16 and React 19 (pinned by MP §2) load 132 KB gzipped on every page before any app code (`rootMainFiles` in the build manifest). Our own JavaScript on the homepage is held to 20 KB in E2E (15 KB measured, down from 25 KB). The total is recorded, and the open decision is Q27.
- A new font family means two steps:
  1. Add it to `src/lib/fonts`.
  2. Rerun `node scripts/generate-font-fallbacks.mjs`.
- Phase 5 builds the appearance screen (picker, live preview iframe, colours, fonts) on `createPreviewToken`, and reruns the checksum harness through the UI.
